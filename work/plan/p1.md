## 1. Architecture

### 1.1 What runs where

```
Visitor browser
   |  (HTTPS, only broadvaleai.com; never calls Supabase)
   v
Cloudflare  DNS + proxy + Turnstile + Web Analytics
   |
   +--> Worker "broadvale-web"  (Next.js 15 via OpenNext)   <-- the one app
   |       pages, /api/* routes, Model gateway, Language module,
   |       Kasoti chat loop, PII masking, limits, admin, cron handler
   |         |-- Supabase (Postgres)  : all data, admin session   [service key]
   |         |-- Anthropic API        : Claude (default)
   |         |-- Google AI (Gemini)   : fallback model
   |         |-- Google Cloud         : Translation, Speech-to-Text, Text-to-Speech
   |         |-- Sarvam AI            : translate, speech (first choice)
   |         |-- Brave Search API     : Kasoti search
   |         |-- AWS SES              : pre-registration + admin emails
   |         '-- Fly.io "broadvale-py" (Mumbai): kasoti package, Panchang,
   |                                    transliteration, daily rates  [X-Service-Secret]
   |
   '--> Worker cron trigger (daily 00:30 UTC) --> POST broadvale-py /rates/refresh
Supabase pg_cron (daily 21:30 UTC = 03:00 IST): delete expired rows
```

| Part | Why it is there | Why not something else |
| --- | --- | --- |
| Cloudflare Workers (OpenNext) | The spec fixes it (H.1). Edge, DNS and wildcard subdomain are already on Cloudflare. | Pages or Vercel add a second host. |
| Supabase | Postgres, RLS, admin login. One data store. | No Redis, no queue, no R2: counts and limits are SQL queries. |
| Fly.io (`bom`) | Python is needed for the risk models, Skyfield and Aksharamukha. No model keys there (H.2). | A Python Worker cannot run numpy and Skyfield data well. |
| AWS SES | One email service for pre-registration and admin alerts (spec 3.3, 4.2). | Supabase's own mail has a tiny rate limit. |
| GCP | Fallback model (Gemini), Translation and Speech (spec 4.2). | |
| Azure | [LATER]. Not used. | |

**Fix 1.** The Worker has a cron trigger. It calls the Python service once a day to refresh `kasoti_rates`. Why: the spec says the Python service refreshes rates, but a Fly machine that sleeps cannot start itself. The cron trigger is part of the same Worker, so there is no new service.

### 1.2 Data flows

**Pre-registration** (`/business`)
1. Browser loads the page. The Turnstile widget (visible) gets a token.
2. `POST /api/preregister` (name, email, company, note, chips, honeypot, token).
3. Server: honeypot empty? Turnstile verify (siteverify). Validate with zod. Lowercase email.
4. `insert ... on conflict (email) do nothing returning id`. If a row came back, send the SES email. If not, send nothing.
5. Reply `{ok:true}` in both cases. Page shows "Thank you. You are on the list."

**Kasoti chat turn** (`/kasoti`)
1. Client `POST /api/kasoti/turn` with `{sessionId?, message | cardAnswer | edit, files?}`. Cookies: `bv_sid`, `bv_lang`.
2. Server checks, in order: module/product switch (`limits`), 6 messages a minute, 20 new sessions a day per IP hash (new session only), visitor Turnstile pass (`visitor_days`), product day cap, session cap.
3. Server masks the text (PII), saves it in `kasoti_messages`. If files came in: one fast-tier vision call reads them, the result is masked and saved as a `file_read` message. The files are dropped.
4. Loop in the Model gateway, under the Kasoti base prompt (G.2). Fast tier asks. Tools:
   - `ask(card)`: server sends SSE event `card` and ends the response. The next request carries the answer.
   - `describe`, `price`: server calls `broadvale-py` (`POST /describe`, `POST /price`).
   - `search`: Brave. `fetch`: server fetches the URL (public only), strips to text, max 20,000 chars. `read_file(n)`: returns the saved masked reading.
   - Switch to the strong tier when the module is known and inputs are done.
5. Every paid call writes `usage_events` and adds to `kasoti_sessions.cost_inr` and `visitor_days.spent_inr`. At 80% of the session cap the loop stops research.
6. Stream events (SSE): `step`, `card`, `text`, `price` (the `price` result, for the page to draw), `done`, `error`.
7. "Share link": `POST /api/kasoti/share` writes `kasoti_quotes`, returns `/kasoti/q/{share_id}`.

**Shiksha app call** (`/shiksha/{app}`)
1. Client `POST /api/shiksha/run` with `{app, params, lang, text?, audio?, image?}`.
2. Server: app switch on, caps, Turnstile pass. Handler by manifest:
   - `llm`: base prompt (G.1) + task prompt + params. If `write` quality for the language is "fair": ask in English, then Language module translates, no streaming. Else stream in the language. If `cache` and chips only: look up `content_cache` by hash first.
   - `rule`: code in `apps/web/src/shiksha/handlers/rule/{app}.ts`, may call the Language module.
   - `content`: read `shiksha_content` (and `translations` for meaning text).
   - `calc`: Panchang calls `broadvale-py /panchang`.
3. Cost goes to `usage_events` and `visitor_days`.

**Translation and speech** (Language module, `apps/web/src/lib/language/`)
1. A call asks for `(task, lang)`. The module reads `language_routes` (cached 60 s in the Worker).
2. Quality "none": returns `{unavailable:true}`; the UI shows "This is coming for your language."
3. Otherwise try providers in order from the route row: Sarvam, then Google, then the model (translate only). On a provider error, go to the next one. Each call writes `usage_events`.
4. Transliteration: `POST broadvale-py /transliterate` (Aksharamukha).
5. Audio from a user goes to the provider once, text comes back, audio is dropped. Text is masked before storage.

## 3. Data

**Rules for all tables**
- Every table: `alter table ... enable row level security;` and **no policies**. The anon and authenticated roles can read nothing. Only the service key (server) can read and write. This meets "no anonymous access" (spec 7).
- Ids: `uuid default gen_random_uuid()` unless stated. Times: `timestamptz default now()`. Days: `date` in IST, written by the server as `(now() at time zone 'Asia/Kolkata')::date`.
- The admin Supabase session is used only to prove who the admin is. All admin reads and writes use the service key after the server checks `admin_users`.

**Daily delete job** (`0005_cron.sql`, runs 21:30 UTC = 03:00 IST):
```sql
select cron.schedule('bv-daily-clean', '30 21 * * *', $$
  delete from kasoti_sessions where created_at < now() - interval '90 days';   -- messages cascade
  update kasoti_sessions set ip_hash = null where ip_hash is not null and created_at < now() - interval '1 day';
  delete from kasoti_messages where created_at < now() - interval '90 days';
  delete from kasoti_quotes where created_at < now() - interval '1 year';
  delete from visitor_days where day < (now() at time zone 'Asia/Kolkata')::date - 1;
  delete from content_cache where created_at < now() - interval '30 days';
  delete from app_interest where created_at < now() - interval '1 year';
  delete from content_reports where created_at < now() - interval '1 year';
$$);
```

**Fix 3.** `limits` is one key-value table for caps and all switches (the spec lists "caps, and on/off per product, app and Kasoti module" for one table). `language_routes` holds the `write` quality as a fifth task row, not a separate table.

**How limits are checked.** Day spend per product = `sum(cost_inr) from usage_events where day = today and product = X`. The Worker caches the result for 15 seconds. Session spend = `kasoti_sessions.cost_inr`. Visitor spend = `visitor_days.spent_inr`. When a product passes 80% and `alert_sent_on` is not today, the Worker sets `alert_sent_on = today` (an `update ... where alert_sent_on is distinct from today returning` so only one request wins) and emails all `admin_users` through SES.

**Who gets which key (done by script, never by hand)**
- Worker secrets: every key except `CLOUDFLARE_*` and `FLY_API_TOKEN`.
- Fly secrets: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `PY_SERVICE_SECRET` only (spec D.1).
- Build time: `NEXT_PUBLIC_*` must exist when `next build` runs, because Next inlines them.
- Local dev: `apps/web/.dev.vars` is generated from `.env` (git-ignored).

**Scripts**
1. `scripts/with-env.sh <cmd...>`: `set -a; . ./.env; set +a; exec "$@"`. Every other script and every `pnpm` task that needs keys runs under it. Next.js does not read the root `.env` by itself, so `pnpm dev` is `../../scripts/with-env.sh next dev`.
2. `scripts/gen-secrets.sh`: for `PY_SERVICE_SECRET` and `IP_HASH_SALT` only, if the value is empty, writes `openssl rand -hex 32` into `.env`. Prints key names, never values.
3. `scripts/sync-env.ts`:
   - reads `.env` (values stay in memory);
   - Worker: builds a JSON object of the Worker keys and runs `wrangler secret bulk` (JSON on stdin) in `apps/web`;
   - Fly: builds `KEY=value` lines and runs `fly secrets import -a broadvale-py` on stdin;
   - also writes `apps/web/.dev.vars`;
   - fails with a list of empty key names if a needed key is empty. Never prints a value.
4. `scripts/deploy.sh` calls `gen-secrets.sh`, `sync-env.ts`, then the deploy commands of section 6.

Rule: a key change is "edit `.env`, run `scripts/deploy.sh`". No other place holds a key.

## 7. Per-product detail

### 7.1 Site-wide rules (all pages)

- **Theme on the server.** `app/layout.tsx` reads cookies and the IST clock: `bv_preview` (`v1`/`v2`) if set and not expired, else Day 06:00-19:00 IST, else Night. It writes `<html data-theme="noir">` for Night. Home ignores this. Pages are dynamic, not cached at the edge.
- **`bv_preview` expiry.** The cookie value is `v1|<unix time of next switch>`. If the time has passed, the server ignores it. (Spec says it lasts "until the next 06:00 or 19:00 IST".)
- **Tokens.** Tailwind 4 `@theme` maps colour names to CSS variables. 13 variables each for Day and Night. Names as in `existing-site.md`: `background card foreground muted muted-fg border sky air field canal mustard banyan on-banyan`.
- **Main button, corners, focus, motion, "never" list**: spec 2.1 and 2.4 as written. One `Button` component with variants `main` and `text`. Day radius 8 px, Night 0 (CSS variable `--r`).
- **Fonts.** `gen-fonts.ts` copies woff2 files from the `@fontsource/*` packages named in spec E.2 into `public/fonts` and writes `fonts.css` with `font-display: swap` and one `@font-face` per file, scoped by `unicode-range` so only the needed script downloads. `layout.tsx` preloads only Latin and Devanagari Mukta and Anek.
- **Symbols.** Three React components that draw the SVG of E.1 with `currentColor` and CSS variables for the accent; the `-24` variants drop the holes, strings and side petals. The files in `public/marks/` are exported from the same path data by `gen-og.ts`.
- **Page metadata.** `generateMetadata` on each page: title, description, `og:image` = `public/og/{page}.png`. Shared quotes and admin: `robots: noindex`.
- **Client JS budget.** Server components by default. Client components only for: theme toggle, language menu, Turnstile, forms, Chat, Composer, Mic, TraceCanvas, QuizCard, Listen. No markdown library: the model replies in a small fixed format (headings, short paragraphs, lists) and `ResultCard` renders it with 60 lines of code. No animation library: CSS only.
- **Language menu.** Writes `bv_lang` = `en|0` (code and large text). The server reads it for `<html lang>`, `dir`, the font set and UI strings. Default: first match of `Accept-Language` in the 23 codes, else `en`.

- **Footer line.** Server component. Calls `/api/panchang` logic directly (same function) with a one-day Worker cache (`caches.default`, key by IST date). If the Python service fails: the line is left out, not an error.
- **Cookies.** Only the four in D.2. `bv_sid` is set by `/api/visitor/pass` (httpOnly, SameSite=Lax, Secure, 1 year).

### 7.6 Kasoti

**Python service** (`services/py`)
- `POST /describe {module}` and `POST /price {module, inputs, research, caution}` as spec C.1. `POST /rates/refresh`, `GET /panchang`, `POST /transliterate`, `GET /health`. All except `/health` need `X-Service-Secret`; compare with `hmac.compare_digest`.
- Package `kasoti`:
  - `base.py`: `Module` base class (`describe()`, `simulate(inputs, research, rng) -> draws`), `PriceResult` dataclass, confidence rules.
  - `mc.py`: `rng = numpy.random.default_rng(20261126)` (the same seed always), `N = 10_000`.
  - `units.py`: ₹ units, lakh and crore helpers, EMI.
  - `loaders.py`: reads `data/*.csv`; reads `kasoti_rates` through the Supabase REST API with the service key.
  - `registry.py`: name -> module; band tables (age band, cover band, income band) as lists of `(label, low, high)`; midpoint is the draw centre.
- **Research figures.** Each `research` entry has `{id, label, unit, low, high, default}`. In `price`: a figure that is missing, null or outside `[low, high]` becomes `default` and counts as one gap. A valid figure `v` is drawn as `v * (1 + N(0, s))` with module spread `s` (below), clipped to `[low, high]`. A defaulted figure is drawn from `triangular(low, default, high)`.
- **Output.** `fair_price` = median of draws, `range` = (p10, p90). `risk_score` = the percentile of the loss draws given by `caution` (90, 75 or 50), clipped to 0-100. `risk_band` = `["very low","low","medium","high","very high"][min(4, int(score // 20))]`. `confidence`: start High (2), minus 1 for each of: gold or loan rate older than 7 days (from `kasoti_rates.day`), a "Not sure" on a required input (input value `"unsure"`), 2 or more gaps; floor Low. `sources` returned = the sources the model passed with each figure.
- Inputs that say "Not sure" take the module default (below) and are listed in `assumptions`. `assumptions` also lists every default and every constant used.

**Formulas and constants** (the reviewers of spec section 9 may change them; every constant is a named variable at the top of its module file, with a comment on its source). `v` below means the draw of a research figure. Band values use the band midpoint.

1. `term_life`. Inputs: age band, sex, smoker, cover band. Term `n = max(10, 60 - age)`. Mortality `q_x` from `data/ialm_2012_14.csv` (IALM 2012-14, by sex and age), times 1.8 if smoker (`SMOKER_LOADING`, constant). Discount rate `i = 6%` (`VAL_RATE`). `PVclaims = C * sum_{t=0..n-1} v^(t+1) * tpx * q_{x+t}`, `annuity = sum v^t * tpx`. Fair yearly premium `= PVclaims / annuity * (1 + e)`, with `e` the research figure `expense_loading` (unit %, low 10, high 45, default 25). Second research figure: `market_rate_per_lakh` (₹ per ₹1 lakh cover a year; low 20, high 200, default 80; shown in `extras` as "insurer quotes seen", not in the price). Spread `s = 0.05`. Unit `₹ a year`. Extra: yearly premium; with an uploaded quote the model passes `quote` (input, number, optional): extra "quote vs fair" = `quote / fair - 1`. Loss: `max(0, 1 - C / (10 * income))`, with `income` from the capacity card band, drawn uniformly inside the band; percent.
2. `gold`. Inputs: item, purity (24K 1.0, 22K 0.9167, 18K 0.75), weight g, making charge quoted (% of metal value). Rate `R` = latest `gold_24k_inr_g` in `kasoti_rates`, drawn with `N(0, 1%)`. Metal value `M = R * weight * purity`. Research: `making_pct` (jewellery low 3, high 25, default 12; coin or bar low 1, high 8, default 3: two modes of one figure chosen by item), `gst_gold_pct` (default 3, low 3, high 3). GST on making 5% (`GST_MAKING`). Fair price `= M * (1 + gst_gold) + M * making * (1 + GST_MAKING)`. Spread `s = 0.04`. Unit `₹`. Extras: fair price against the quote (if the model passes `quote_total`), "making charge is fair" = quoted % <= p90 of draws of `making_pct`. Loss: `(P - 0.98 * M) / P` (`DEALER_DISCOUNT = 2%`).
3. `used_vehicle`. Inputs: make and model, year, km band, asking price. Owners default 1. IDV depreciation by age (IRDAI schedule, `data/idv_dep.csv`): up to 6 months 5%, 1 year 15%, 2 years 20%, 3 years 30%, 4 years 40%, 5 years 50%; beyond 5 years: 50% + 5% a year, capped at 80%. Research: `new_price` (₹; low 1.5 lakh, high 3 crore, default: none, so a gap sets confidence and the price uses the median listing), `market_median` (₹, median of 3+ public listings for model, km and city; same limits). Value `V = new_price * (1 - dep(age))`. Adjusters: km (below 8,000/yr 1.03, 8,000-15,000 1.0, above 1.0 -> 0.95), owners (1: 1.0, 2: 0.95, 3+: 0.9). Fair price = median of `0.4 * V_adj + 0.6 * market_median` (if `market_median` exists, else `V_adj`). `s = 0.07`. Unit `₹`. Extras: asking vs fair range, drivers (age, km, owners, with the percent each moves the price). Loss: `max(0, (ask - fair_draw) / ask)`.
4. `motor`. Inputs: vehicle, year, city, no-claim-bonus band. Research: `tp_premium` (₹ a year, the IRDAI third-party rate for the vehicle's engine band: low 1,500, high 15,000, default 3,416), `od_rate` (own-damage rate on IDV, %, low 1.5, high 5, default 3.0), `idv_base` (the vehicle's market value for IDV, ₹; if missing the model uses module 3's `new_price` path). NCB discount by band (0, 20, 25, 35, 45, 50 %). `OD = IDV * od_rate * (1 - ncb)`. GST 18% on both parts. Premium `= (TP + OD) * 1.18`. `s = 0.06`. Unit `₹ a year`. Extras: split third party / own damage; add-ons worth it by rule: zero depreciation if age <= 5 years, engine protect if city in a flood-prone list (`data/flood_cities.csv`), roadside always listed as optional. Loss: `(deductible + parts_share * dep_share * bill) / bill`, with repair bill `~ lognormal(median 40,000, sigma 0.7)`, `deductible = 1,000`, `parts_share = 0.6`, `dep_share = 0.25`.
5. `health`. Inputs: member age bands (multi-chip), city tier, known conditions, cover band. Research: `premium_{band}` for each of six bands (0-17, 18-35, 36-45, 46-55, 56-65, 66+) = published yearly premium per member for a 5 lakh cover (low 2,000, high 80,000; defaults 4,500 / 6,500 / 9,500 / 14,000 / 21,000 / 33,000), `claim_ratio` (%, low 40, high 120, default 85; `extras` only). Premium `= sum_members premium_band * (cover / 5 lakh)^0.6 * tier * cond`, tier T1 1.0, T2 0.85, T3 0.75, cond 1.25 if conditions. `s = 0.08`. Unit `₹ a year`. Extras: range; checklist "waiting period, room-rent limit, co-pay" as fixed text; the insurer's claim record (from `claim_ratio` and its source). Loss: `(max(0, bill - cover) + 0.10 * min(bill, cover)) / bill`, `bill ~ lognormal(median by tier T1 3 lakh, T2 2 lakh, T3 1.5 lakh; sigma 0.8)`.
6. `home`. Inputs: kind, city, area band (built-up), rebuild cost band. Research: `rate_per_mille` (premium per ₹1,000 of sum insured, low 0.2, high 3.0, default 0.8; Bharat Griha Raksha). Sum insured `SI = rebuild band midpoint`. Premium `= SI / 1000 * rate * (1.0 flat, 1.15 house) * 1.18`. `s = 0.10`. Unit `₹ a year`. Extras: premium range; "sum should equal rebuild cost, not market price" with the number SI. Loss: `max(0, 1 - SI / rebuild_draw)` where `rebuild_draw ~ lognormal(median SI, sigma 0.15)`.
7. `personal_loan`. Inputs: amount band, tenure, monthly income band, credit score band (750+, 700-749, 650-699, under 650, "no score"). Research: `rate_low`, `rate_mid`, `rate_high` (% a year, published bank and NBFC personal-loan range; low 7, high 36; defaults 10.5, 13, 18). `repo` from `kasoti_rates` is a floor: `rate >= repo + 2`. Score shift in points: 750+ -1.0, 700-749 0, 650-699 +2.0, under 650 +4.0, none +1.0. Fair rate = median of `triangular(rate_low, rate_mid, rate_high) + shift`. `s = 0.05`. Unit `% a year`. Extras (computed at the median): EMI `= P * r * (1+r)^n / ((1+r)^n - 1)` with `r = rate/12`, total interest, EMI/income, quoted rate vs fair (input `quote` optional). Loss: `EMI(rate + 2) / income`, scaled `min(100, share / 0.40 * 60)`.
8. `business_loan`. Inputs: amount band, tenure, yearly turnover band, years in business. Research: `rate_low`, `rate_mid`, `rate_high` (published MSME loan rates; defaults 9.5, 12, 18). Years in business shift: under 2 years +1.5, 2-5 +0.5, over 5 -0.5. Same EMI formula. Extras: EMI; schemes to ask a bank about, as a fixed labelled-example list: MUDRA (Shishu to ₹50,000, Kishor to ₹5 lakh, Tarun to ₹10 lakh) and CGTMSE cover; the build checks the limits on the official pages and updates the list. Loss: `yearly repayment (rate + 2) / turnover`, scaled `min(100, share / 0.10 * 60)`.
9. `analogue`. Input: `research.prices = [{value, source}]` (3 to 10). Fewer than 3: return `{no_number: true}`. Else median, p10-p90, `risk_score = min(100, (p90 - p10) / median * 100)`, `confidence = "Low"`, label "Estimate, no model".

Data files in `services/py/data/` (the agent fetches them at M12 and cites each in `assumptions` and in `kasoti_sources`): `ialm_2012_14.csv` (IAI; if the table cannot be fetched, fit a Gompertz-Makeham curve to the published ages of 20, 30, 40, 50, 60 and log it), `idv_dep.csv`, `tp_premiums.csv` (IRDAI notification), `flood_cities.csv`, `bands.json`.

**Gold and repo rates** (`rates.py`): gold = IBJA published daily rate (`ibjarates.com`, 24K, ₹ per 10 g, divide by 10); repo = RBI "Current rates" page. If a fetch fails the old row stays; `confidence` then drops after 7 days. If IBJA cannot be read, the old row stays and `confidence` drops after 7 days.

**Next.js side** (`apps/web/src/kasoti`)
- `loop.ts`: the loop of spec 5.4. Turn = load `kasoti_messages` by `session_id` -> Model gateway call with tools -> run tool calls -> repeat until the model stops or calls `ask`. Hard limits: 12 tool rounds per turn; `fetch` 6 pages per turn; 5 `search` calls per turn.
- Tiers: fast tier for the first part (need, reason, capacity, inputs, tone). The loop switches to the strong tier from the first `describe` result with all required inputs known: it is a flag on the session (`kasoti_sessions.module` set and `tone` answered).
- `tools.ts`: JSON schemas for `ask`, `describe`, `price`, `search`, `fetch`, `read_file`; `price` input includes `research` as `[{id, value, source_url, source_title, source_date, note}]`.
- `fetch`: server-side `fetch` with a 10 s timeout and a 2 MB limit, only `http(s)`, blocks private IP ranges and `localhost`; HTML to text by a small stripper; PDF pages: not read (skip; say "I could not read X").
- `prompt.ts`: G.2 text exactly, with `{language}`, `{date}`, `{modules}` filled per call (`{modules}` = modules whose `sw.module.*` is on, plus `analogue`).
- Language of reply: `detect.ts` takes the last user message: script block -> language when the script maps to one language (Tamil, Telugu, etc.); Devanagari, Bengali-Assamese, Perso-Arabic, Latin: use Google `detectLanguage` (cost logged); Latin text maps to English when the detector says an Indian language written in Latin (Hinglish gets English). Voice input: the transcript language is the one the transcription provider returns.
- Page parts: `PriceLine` renders the three line forms by `unit` from the `price` event; `RiskBar` is 5 segments with the band filled; confidence as a word; folded sections in `details` elements; the disclaimer line from spec 3.5 under every answer; `Beta` or "Estimate, no model" label by `review_marks` / module.
- Quotes drawer: `localStorage` key `bv_quotes` (last 20 `{share_id?, module, title, created_at, answer}`); "Old data. Re-price to update." when older than 7 days.
- Save as PDF: `window.print()` with a print stylesheet (hide composer and nav).
- Push-to-talk: `MediaRecorder` (webm/opus or mp4 on Safari), max 60 s, Space key when the composer text box is not focused; POST audio to `/api/shiksha/transcribe` (shared route, name kept for both products) with `product=kasoti`.
- Files: up to 3, PDF 10 MB and at most 5 pages (page count read from the PDF header on the server; reject over 5), photo 8 MB; sent as multipart on the turn; server sends them to the fast tier once as `document` / `image` blocks; the answer (what was read) is a JSON of labelled values, masked, saved; the file is never written to disk or DB.
- Caps and limits as in spec 5.4 and section 3. Messages: "I could not reach X. I used what I have.", "Please try again in a minute." (both model tiers failed), "This chat is full. Please start a new one."
- Help line for distress: the base prompt (G.2 rule 6) makes the model write it. The page adds nothing.
