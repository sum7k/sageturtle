  - Shiksha: Saraswati with the veena and a lotus.
- Use plain line art made by us, as SVG. Do not use photos of deities. No stock clip art.
- Each product page opens with one short Sanskrit line in Devanagari, with its meaning below in English. Lines to use:
  - Surya: "तमसो मा ज्योतिर्गमय" (from darkness, lead me to light).

## 3. Surya

### 3.1 What it is
AWS of India, AI native. It is used only by API or MCP. It gives every part an app needs, so an AI agent can take a proof of concept to production on a name under `*.broadvaleai.com`. It is not public. Billing is internal. Kasoti and Shiksha are its first customers.

### 3.2 Products (building blocks) [LATER, except 3.5]
Use the list from `docs/context/surya-idea.md`: Storage, Database, Context memory, RAG, Training, Evaluation, Key management, Human-in-the-loop dashboard, Monitoring, User analytics, Authentication, Model gateway, Background jobs, Guardrails, Rate limits, Domain, Email and notifications, Environments, Backup and restore, Teams and audit log. Add one more for India: **Language** (translate, transcribe, speak, in all Indian languages). Shiksha needs it first.

### 3.3 Placement engine [LATER]
- Each product has a driver per backend: Supabase, Cloudflare, AWS, GCP, Azure, Fly.io.
- The engine picks the backend by purpose and cost. Rule of thumb: Supabase for relational data and auth. Cloudflare for edge, static, object storage and DNS. Fly.io for small long-running services. AWS, GCP, Azure for what only they offer (for example speech models, GPU, managed training).
- The user never sees the backend. The engine keeps a cost table, updated by hand at first.

### 3.4 Access model [LATER]
- API and MCP server with the same capabilities. An API key per app. Keys are created in the dashboard.
- Flow and hard rules: as in `docs/context/surya-idea.md` (agent proposes, human approves on a Surya page, Surya applies, spend limits, no secrets to the agent).
- Dashboard after login: create an API key, see apps and products, see balance and usage, read the help docs "from POC to production on a name on our subdomain".
- Deploy target: `appname.broadvaleai.com`, TLS by Cloudflare.

### 3.5 Phase 1 slice of Surya [NOW]
Build only what Kasoti and Shiksha need, as internal modules with clean boundaries so they can later become Surya products:
- Model gateway: one function for all LLM calls, with provider fallback, cache, per-session spend limit and cost log.
- Language: translate, transcribe, speak.
- Storage and Database through Supabase.
- Monitoring: a `usage_events` table (product, app, model, tokens, cost, time).
- Subdomain routing: `kasoti.` and `shiksha.` are not needed. Both live under paths `/kasoti` and `/shiksha`. Apps get `name.broadvaleai.com` through a Cloudflare wildcard route. [NOW for the wildcard, LATER for dynamic apps]

### 3.6 Internal billing [NOW minimal]

## 4. Kasoti

### 4.1 Purpose
A risk pricing engine for any asset, for Indian users, businesses and institutions. Examples: a health or term policy, a loan, a used car, a house, a gold purchase, a startup share, a crop, a business interruption, a cyber risk.

### 4.2 Library [NOW]
- A Python package `kasoti` of modules. Each module prices one family of assets. Shared parts: data loaders, a risk model base class, a result schema, units and currency in INR.
- Module interface: `describe()` returns the questions it needs. `price(inputs)` returns `{fair_price, range, risk_score, drivers, assumptions, confidence}`.
- Methods: rule-based and actuarial tables where they exist, plus Monte Carlo for ranges. LLM is used for reading documents and for missing data, never for the final number.
- Phase 1 modules (pick eight): term life, health cover, motor, home, gold, personal loan, small business loan, used vehicle value. Others [LATER].
- A router picks the module from the user's words. If none fits, it falls back to a generic "analogue" method: find comparable assets by web research and reason from them, with a clear label "estimate, no model".

### 4.3 Chat interface [NOW]
- Looks like a modern LLM chat: wide empty canvas, one message box at the bottom, streaming answers. Calm, Krishna symbol at the top, no clutter.
- **Push-to-talk button** beside the box: hold to talk, release to send. Speech to text with a model that supports Indian languages. Answers can be read aloud with a speaker button. Falls back to typing.
- Language: the user may write or speak in any Indian language. The reply comes in the same language.
- Uploads: photo or PDF of a policy, a quote, a bill. [NOW for PDF and images]

### 4.4 Conversation flow
1. The user states what they want priced.
2. Kasoti asks easy questions, one at a time, with tap-to-answer chips: need, capacity (budget, income band, savings), tone (how much detail, how careful), and reason.
3. It stops asking when the module's inputs are filled. It never asks more than eight questions.
4. It runs the work: tool calls to the module, web research, and a deep analysis step.
5. It shows the answer.

### 4.5 Answer format [NOW]
Depth follows the user's capacity and choice (a slider "Short / Detailed / Expert").
- Top: one sentence "Pay about ₹X (range ₹A to ₹B)" and one sentence of risk "You take a medium risk because ...".
- Below, collapsible: how the price was built, main risk drivers, what could change it, what to ask the seller, sources with links, and assumptions.
- A small bar showing the risk level. No jargon in the short level. Terms are explained inline in the expert level.
- Buttons: "Change an input and re-price", "Save", "Share as PDF". [NOW for first and third]
- A short note: "This is guidance, not financial or legal advice."

### 4.6 Backend [NOW]
- Tool calling loop through the Model gateway. Tools: module pricing, web search and fetch, calculator, document reader.
- Deep analysis: a second, stronger model reviews the number against the research and flags gaps.
- Stored: `kasoti_sessions`, `kasoti_messages`, `kasoti_quotes` (inputs, output, sources, cost). Session is anonymous in phase 1.
- Limits: a per-session cost cap and a rate limit by IP.

## 5. Shiksha

### 5.1 Purpose
121 small education apps, free of login, in every Indian language. Content is translated or transcribed on demand.

### 5.2 Languages [NOW]
- The 22 scheduled languages of India plus English: Assamese, Bengali, Bodo, Dogri, Gujarati, Hindi, Kannada, Kashmiri, Konkani, Maithili, Malayalam, Manipuri (Meitei), Marathi, Nepali, Odia, Punjabi, Sanskrit, Santali, Sindhi, Tamil, Telugu, Urdu, English.
- Add more [LATER]: Bhojpuri, Rajasthani, Tulu, Khasi, Mizo.
- A language switcher in the nav, with each language written in its own script. The choice is remembered.

### 5.3 Language on demand [NOW]
- UI strings are written once in English and translated by the Language product on first use, then cached in the table `translations` (key, language, text, reviewed flag). A human can mark a row reviewed.
- User content (a lesson, a question, a voice note) is translated or transcribed when asked. Result is cached by hash.
- Voice: speech to text and text to speech per language. A "listen" button on any text.
- Right-to-left layout for Urdu, Kashmiri, Sindhi.

### 5.4 Shiksha page [NOW]
- Saraswati line art, the Sanskrit line, then a calm grid of the 121 apps in categories (see appendix). A search box and a category filter.
- Each app is one card: name, one line, language chip. Opens in the same shell.
- Phase 1 builds **the shell and 30 working apps** (the apps marked NOW in the appendix). The others show "Coming soon" and a "notify me" email box that writes to `app_interest`.

### 5.5 App shell [NOW]
- Each app is a module with a manifest: id, name (per language), category, inputs, a function on the server. Apps share the shell: language switch, voice button, save to browser, share link, print.
- Most apps are one screen and call the Model gateway with a fixed prompt, so adding an app costs little.
- No login. Progress is saved in the browser (local storage). [NOW] Sync to an account [LATER].

## 8. Decisions log (round 1)
1. Stack: Next.js on Cloudflare, Python FastAPI on Fly.io for Kasoti. Same as the live site, and Python is a hard need.
2. Theme use: both themes exist on every page. Home shows both. Other pages follow the live site's clock rule with a manual toggle.
3. People side has no button, only "Coming soon".
4. Phase 1 has no public login. Kasoti and Shiksha are anonymous. Reason: Surya is closed, and friction hurts adoption.
5. Pre-registration: anonymous insert only, with Turnstile and honeypot, to keep the table clean.
6. Languages: 22 scheduled languages plus English. Clear, finite list.
7. Kasoti: LLM never sets the final number. Reason: trust and repeatability.
8. Kasoti question cap: eight.
9. Deity images: line art by us, no photos. Reason: respect.
10. Shiksha: ship 30 apps in phase 1, the rest later.
11. Surya in phase 1 is only internal modules. Full platform is later.
