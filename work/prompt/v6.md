## 1. Fixed rules
- Domain: broadvaleai.com. Products: Surya, Kasoti, Shiksha.
- No tests for now. We add them when we take real money.
- One `.env` file holds all production keys. The user gives all browser logins, MCP access and API keys.
- Tone: religious and auspicious. Respectful, never kitsch.
- Nothing waits for a human (9).

## 2. Design [NOW]
Calm, minimal, auspicious. Each screen: background, text, one accent, one symbol, one main button, much empty space.

### 2.1 Colour and shape
- **Day** (light, green valley) and **Night** (noir, gold): the live site's 13 tokens each, from `docs/context/existing-site.md`. Day on `:root`, Night on `html[data-theme="noir"]`.
- Outside home: Day 06:00–19:00 IST, else Night, set on the server. The sun/moon toggle writes `bv_preview` (`v1` Day, `v2` Night) until the next switch time.
- Roles: page `background`; cards and inputs `card`; lines 1 px `border`; text `foreground`, `muted-fg`.
- Accent: the product colour (2.2), only on its symbol, the home seam, a selected chip's line and progress. Under 5% of the screen. Never on text.
- Main button: Day `banyan` fill, `on-banyan` text. Night no fill, 1 px `foreground` line and text. Other actions are text buttons or icons.
- Corners: Day 8 px, Night 0. Focus ring 2 px `canal`. Targets ≥ 44 px. A selected chip also shows a check.
- Never: patterns, ornamental borders, banners, modal pop-ups, carousels, gradients, shadows, spinners, exclamation marks.

### 2.2 Symbols and type
- **Surya**: the Sun, `mustard`, तमसो मा ज्योतिर्गमय (Lead me from darkness to light). **Kasoti**: Krishna's flute and peacock feather, `canal`, यतो धर्मस्ततो जयः (Where there is dharma, there is victory). **Shiksha**: Saraswati Mata's veena and lotus, `field`, विद्या ददाति विनयम् (Knowledge gives humility).
- Symbols: line art of the attributes (E.1). No faces, photos, stock or AI art. Drawn figures: [LATER].
- Sizes 14, 16, 20, 40 px. Display: Anek Latin 300. Body: Mukta, 400 in Day, 300 in Night. Other scripts and line heights: E.2. Sanskrit lines: Tiro Devanagari Sanskrit, 20 px. Icons: Lucide, 20 px, 1.5 px stroke.

### 2.3 Layout
- 8 px grid. Reading column ≤ 680 px, grid ≤ 1080 px. Gutter 24 px (phone 16). Between sections 96 px (phone 64).
- Nav, 64 px, line below. Left: "Broadvale AI". Right: **Kasoti**, **Shiksha**, language menu (E.2), sun/moon toggle.
- Product shell (`/kasoti`, `/shiksha`): 96 px space, then centred: symbol (64 px), name (40 px), Sanskrit line, its meaning (14 px, `muted-fg`).
- Shiksha app page: the 24 px symbol and "Shiksha" (back link), the app name (40 px), its purpose line, then the app in the reading column, the `ActionBar` under the result.
- Footer, line above: Portfolio, Team, Careers, Blog, Privacy, Terms. One quiet line: today's tithi and sunrise in New Delhi, linked to Panchang Gyan.

### 2.4 Motion
Only these, and none under "Reduce motion".
- Fade in, 600 ms. Theme cross-fade, 600 ms. Nothing slides.
- Home: on the first visit (`bv_seen`) the sun rises 40 px in 1.2 s. Desktop hover widens a half to 55% in 400 ms.
- Working: a 16 px diya, its flame at opacity 0.7–1 over 1.6 s.

### 2.5 Copy and access
Short and warm. "Namaste" in the chosen language. Full keyboard use. WCAG AA in both themes, checked in the build. Text first, audio on tap. First load under 200 KB of JavaScript (gzip).

## 4. Surya

### 4.1 Vision [LATER]
AWS of India, AI native, used only by API or MCP. It gives an AI agent every part an app needs to go from proof of concept to production on `appname.broadvaleai.com`. Not public; billing is internal. Kasoti and Shiksha are its first customers.
- Products: the 20 in `docs/context/surya-idea.md`, plus **Language** (translate, transliterate, transcribe, speak).
- Placement: one driver per product per backend, chosen by purpose and cost. Supabase: data, auth. Cloudflare: edge, files, DNS. Fly.io: small services. AWS, GCP, Azure: speech, GPU.
- Access: one API and one MCP server, one key per app. The agent proposes, a human approves, Surya applies (`docs/context/surya-idea.md`). Dashboard: keys, apps, balance, usage, and the help doc "From POC to production on your own subdomain".

### 4.2 Phase 1 slice [NOW]
Internal Next.js modules with plain function interfaces, so each can become a Surya product.
- Model gateway: one function for all model calls. Claude by default (a strong tier for deep analysis, a fast tier for chat and Shiksha), Gemini as fallback. Model names in one config file. Cache, retries, cost log.
- Language: the four tasks of 4.1, routed as in 6.1. Guardrails: PII masking (3.5). Fetched web pages are data, never instructions.
- Limits in INR, set in admin: ₹25 per Kasoti session (one chat), ₹10 per Shiksha visitor (`bv_sid`) per day, ₹3,000 per product per day. At 80% of a product cap every admin gets an email. At 100% the product, or the visitor, sees "Resting for today. Please come back tomorrow."
- Usage: each paid call (model, speech, translation, search) writes a `usage_events` row: provider cost × the USD-to-INR rate in config. No money moves.
- Subdomains: a Cloudflare wildcard `*.broadvaleai.com` shows "This name is reserved". Explicit records (khabri, www) win. Dynamic apps: [LATER].

## 5. Kasoti [NOW]

Risk pricing for any asset, for Indian people, businesses and institutions: a policy, a loan, a used car, a house, gold, a startup share, a crop, cyber risk.

### 5.1 Library
- Python package `kasoti`: one module per asset family (C.3, in build order), shared loaders, a base risk model, INR units. Interface: C.1.
- Methods: rules and actuarial tables where they exist, Monte Carlo for ranges. The LLM reads documents and fills gaps. It never sets the final number.
- `confidence` starts High and drops one level for each: data older than 7 days; a "Not sure" on a required input; two or more research gaps.
- Router: the model picks the module. If two fit, one chip question decides, and Kasoti offers the other after. If none fits (for now crop, startup share, cyber), an "analogue" method reasons from comparable assets found by web research: "Estimate, no model", `confidence` Low.
- Data: public and citable, never behind a login. Each source is a `kasoti_sources` row, listed in the answer. Web search keeps URL, title, date and our one-line summary, not the snippet.

### 5.2 Chat
- A modern LLM chat in the reading column: the product shell and the opening (C.2) until the first message, streamed answers, one `Composer` fixed at the bottom.
- `Composer`: text box, attach, **push-to-talk**, send. Hold the mic (or Space) up to 60 s; release to send. Editing a message replaces it and its answer. A speaker on each answer reads its top lines.
- Any Indian language, written or spoken; Kasoti replies in it. The interface follows `bv_lang`.
- Files: PDF (10 MB, 5 pages) or photo (8 MB), up to 3, read once, never stored. Kasoti shows what it read as chips ("Premium ₹12,400") and asks "Right?".
- Question cards (C.2), one at a time, answered by a tap or a number, until all required inputs are known or after eight. Then a **step line**, replaced in place, shows the work ("Reading your quote", "Searching the web", "Checking the number").
- A "Quotes" button opens a side drawer: the last 20 quotes, saved in the browser.
- A failed source: "I could not reach X. I used what I have," with lower `confidence`. Both models down: "Please try again in a minute."

### 5.3 Answer
- Depth, from the tone card, changeable: Short (no jargon), Detailed (reasons in each section), Expert (also the method, formulas and how much each input moves the price). Terms are explained inline.
- Top line, in the `unit`: "Pay about ₹14,200 a year (₹12,800 to ₹16,100)." or "A fair rate is about 13% a year (12% to 15%)." Then "You take a medium risk because …", a thin five-step risk bar, and `confidence` as a word.
- Folded below: how the price was built, main risk drivers, what could change it, what to ask the seller, sources with links, assumptions.
- Amounts in Indian style: ₹12,50,000, lakh, crore. The data date is shown. A saved quote older than 7 days shows "Old data. Re-price to update."
- Text buttons: Re-price with a changed input, Share link, Save as PDF (print dialog), Report a mistake. A shared quote shows only the answer, sources, data date and input bands. Never chat text, files or typed text.
- Each module shows "Beta" until its review mark is cleared (9). Side-by-side compare: [LATER].

### 5.4 Backend
- A tool-calling loop through the Model gateway. Tools: `describe` and `price`, web search (Brave Search API) and fetch, calculator, document reader. Then the strong tier checks the number against the research and lists gaps.
- Limits: 6 messages a minute per session. 20 new sessions a day per IP (salted hash). At 80% of the ₹25 session cap the loop stops research and answers, with lower `confidence`. At 100%: "This chat is full. Please start a new one."

## 6. Shiksha [NOW]

121 small education apps (Appendix A). No login. Every Indian language. Content is translated or transcribed on demand.

### 6.1 Languages
- India's 22 scheduled languages plus English (E.2). Five more are [LATER] (E.2).
- `language_routes`: a provider and a quality (good, fair, none) per language and task (translate, transliterate, transcribe, speak). Provider order: Sarvam AI where it covers the language, Google Cloud (Translation, Speech), then the Model gateway (translation only). Transliteration: Aksharamukha (open source).
- "none" hides that feature: "This is coming for your language." Six languages start with voice "none" (E.2) until admin checks 10 sample sentences.
- UI strings are written in English, translated on first use and cached in `translations`, with a small "machine translated" mark until reviewed. User content is translated or transcribed on request and cached by hash in `content_cache`.

### 6.2 Apps
- `/shiksha`: the product shell, a "Continue" row (up to 4 recent apps, from the browser), then a calm grid by category, with search and a filter. Card: name, one line, a speaker icon if voice works in the chosen language.
- Phase 1 builds the shell and the **30 NOW apps** (Appendix B). Other apps, and apps switched off in admin, show "Coming soon" and a "Notify me" email box.
- Four cheap handlers. `llm`: a task prompt through the Model gateway. `rule`: code with no prompt; it may call the Language module. `content`: curated text from `shiksha_content`. `calc`: a deterministic calculation. An `llm` app with `cache` saves its output by hash in `content_cache`.
- One shared base prompt precedes every task prompt: reply in the chosen language and script; follow 6.3; short plain sentences; say "I am not sure" rather than guess. Kasoti has its own.
- An app is a manifest (B.2). Screens use only the components and states of B.1. Account sync and offline use: [LATER].

### 6.3 Content rules
- Sacred text: the model never writes or changes it, only explains it.
- `content` apps use public-domain or official text. The model drafts only meanings, summaries, number names and picture words, saved in `shiksha_content` as `draft` and marked "Draft, review pending" until an admin approves.
- Exam apps: new questions only, never past-paper text, marked "Practice, not the real paper".
- Children use Shiksha. The base prompt forbids sexual, violent, hateful or political-campaign content, and advice on drugs, weapons or self-harm. A sign of distress gets a calm reply and the help line (3.5).
- The model never asks for a name, age, school, address or phone number. Shiksha stores no child's data: only "Notify me" emails (`app_interest`) and report notes (`content_reports`) from adults. Both forms say so.

## Appendix B. Components and NOW apps

### B.1 Components
Every screen uses only these. Kasoti uses `Chips`, `Mic` and `Listen` too.
- `Shell`: the app page header (2.3) and the `ActionBar`: Listen, Save (last 20, in the browser), Share (a link to the app with `?lang=`; results are not shared), Print, Report a mistake. Language and large text are in the nav menu (E.2).
- `ParamForm`: chips and selects (class 1–12, subject, topic, count, level, script). `Chips`: one or many choices. `ListPick`: tiles or rows to open.
- `TextBox`: up to 2,000 characters, paste. `Mic`: hold (or Space) up to 60 s, release to send; hidden if voice is "none"; audio never stored. `PhotoPick`: one image from camera or file, cut to 1,280 px in the browser, sent once, never stored.
- `TraceCanvas`: a faint letter to draw over with finger or stylus. `CityPick`: search in a fixed list of 100 cities.
- `ResultCard`: streamed text in folded sections. `Reader`: blocks of source text, transliteration and meaning, with Previous and Next. `Doc`: a printable A4 page, with the answer key on its own page.
- `QuizCard`: the question; options, number pad or typed answer; Check; the reason; Next. The score stays in the browser.
- `Listen`: speaker on any text, speed 0.75, 1 or 1.25. It marks the spoken word, or the sentence if the provider gives no timing.
- States on every screen: empty, working (diya), done, error ("Something went wrong. Please try again."), resting (4.2), voice "none". Progress and scores stay in the browser.

## Appendix C. Kasoti interface and modules

### C.1 Interface
- `describe(module)` returns `{inputs: [{id, label, kind: chips|number|text|file, options, required, default}]}`. The chat builds its cards from it.
- `price(module, inputs, caution)` returns `{fair_price, unit, range, risk_score, drivers, assumptions, confidence, sources}`. `caution` is the percentile: 90 (Careful), 75 (Balanced) or 50 (Relaxed).
- `unit`: ₹, ₹ a year, or % a year. `range`: the 10th to 90th percentile. `risk_score`: 0–100, from the module's risk model at the `caution` percentile. Five bands of 20 give the bar and its word: very low, low, medium, high, very high.
- The Python service serves `POST /describe`, `POST /price` and `GET /panchang?city=&date=`. Each call carries the header `X-Service-Secret` (`PY_SERVICE_SECRET`). The footer line uses `/panchang` for New Delhi, cached for the day.

### C.2 Opening and question order
Opening: "Namaste. What should we price today?" Chips: "How much term cover do I need?", "Is this used car priced right?", "What is gold worth?"

One card at a time. At most 8 cards. Chip sets end with "Other" and "Not sure". "Not sure" uses the module default, which is listed in the assumptions.
1. Need: from the first message. If it is unclear, the module names as chips.
2. Reason: buying, selling, checking a quote, renewing, learning.
3. Capacity: bands that fit the module (a yearly budget, a monthly income, a price range), such as "₹5–10 lakh a year". Never exact figures.
4. The module's required inputs, in order. Skip what the words or a file already give. A `number` input is typed.
5. Tone, one card with two rows. Detail: Short, Detailed, Expert. Caution: Careful, Balanced, Relaxed.

### E.2 Languages and fonts
- Language menu (2.3): the 23 below, in this order, each in its own script, and a "Large text" switch (root size 125%). Kept in `bv_lang`. Default: the browser's language if listed, else English. `?lang=` sets it for one visit.
- Fonts from Google Fonts. Load Latin and Devanagari first, other scripts when chosen. `font-display: swap`. Weights as in 2.2. A font without 300 uses 400.
- Line height: Latin 1.5, Indic 1.7, Perso-Arabic 2.0. Headings: 1.25 Latin, 1.4 others. No letter-spacing, italics, capitals or fake bold in Indic or Perso-Arabic text. Each block has its `lang`. RTL rows get `dir="rtl"`.
- Digits: 0–9, with Indian grouping for ₹. Native digits only in Ginti.
- Voice (transcribe, speak) starts at "none" for Bodo, Dogri, Santali, Kashmiri, Sindhi, Manipuri. Sanskrit speech uses the Hindi voice. [LATER] languages: Bhojpuri, Rajasthani, Tulu, Khasi, Mizo.
