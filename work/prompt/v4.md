# Broadvale AI — product prompt v4

**[NOW]** = build in phase 1. **[LATER]** = design only. A heading's tag covers the lines under it.

## 1. Fixed rules
- Domain: broadvaleai.com. Products: Surya, Kasoti, Shiksha.
- No tests for now. We add them when we take real money.
- One `.env` file holds all production keys. The user gives all browser logins, MCP access and API keys.
- Tone: religious and auspicious. Respectful, never kitsch.
- Nothing waits for a human (9).

## 2. Design [NOW]

### 2.1 Themes
- **Day** (light, green valley) and **Night** (noir, gold), the themes of the live site. Use the 13 tokens of each, names and values, from `docs/context/existing-site.md`.
- CSS variables: Day on `:root`, Night on `html[data-theme="noir"]`.
- Pages other than home: Day 06:00–19:00, Night 19:00–06:00. A sun/moon toggle in the nav overrides the clock.
- Cookie `bv_preview` keeps the choice (`v1` Day, `v2` Night), as on the live site.

### 2.2 Product marks
- **Surya**, the Sun. Accent `mustard`. A sun disc with 12 fine rays. तमसो मा ज्योतिर्गमय: lead me from darkness to light.
- **Kasoti**, Krishna. Accent `canal`. A flute with one peacock feather. यतो धर्मस्ततो जयः: where there is dharma, there is victory.
- **Shiksha**, Saraswati Mata. Accent `field`. A veena with a lotus. विद्या ददाति विनयम्: knowledge gives humility.
- Symbols: SVG line art of the traditional attributes, in theme colours. Human-drawn figures of Krishna and Saraswati: [LATER]. No photos, stock art or AI-drawn faces.
- A product page opens with its symbol and line, and the meaning in the user's language. Font: Tiro Devanagari Sanskrit, loaded only for these lines.

### 2.3 Rules
- Per screen: background, text, one accent (under 5% of the area), one symbol, one main button. Much empty space.
- Never: patterns, ornamental borders, banners, pop-ups, carousels, shadows, gradients, spinners, exclamation marks.
- Text is `foreground` or `muted-fg`. Accents never carry small text. The build checks WCAG AA contrast in both themes.
- 8 px grid. Reading width ≤ 680 px, grid ≤ 1080 px. Lines: 1 px, `border`. Night has sharp corners.
- Type: 14, 16, 20, 40 px. Display: Anek Latin 300. Body: Mukta. Other scripts: Noto Sans of that script, loaded when needed.
- Icons: Lucide, 1.5 px stroke.
- Motion: 600 ms fades only, none under "Reduce motion". Bell on first entry: [LATER], off by default.
- Loading: a small diya flame with a soft pulse.
- Copy: short and warm. Greet with "Namaste" in the chosen language.
- Full keyboard use. A "large text" toggle. First load under 200 KB of JavaScript. Text first, audio on tap.

## 4. Surya

### 4.1 Vision [LATER]
AWS of India, AI native, used only by API or MCP. An AI agent gets every part an app needs to go from proof of concept to production on `appname.broadvaleai.com` (TLS by Cloudflare). Not public. Billing is internal. Kasoti and Shiksha are the first customers.

- Products: the 20 in the table of `docs/context/surya-idea.md`, plus **Language** for India (translate, transliterate, transcribe, speak).
- Placement: one driver per product per backend. The engine picks by purpose and by a cost table, edited by hand at first. Defaults: Supabase for relational data and auth. Cloudflare for edge, static files, object storage, DNS. Fly.io for small long-running services. AWS, GCP, Azure for what only they give (speech, GPU, training). The user never sees the backend.
- Access: one API and one MCP server with the same abilities. One key per app. Flow and hard rules: as in `docs/context/surya-idea.md`. The agent proposes, a human approves, Surya applies.
- Dashboard: create API keys, see apps, products, balance and usage, read the help doc "From POC to production on your own subdomain".

### 4.2 Phase 1 slice [NOW]
Internal modules with plain function interfaces, so each can become a Surya product later.
- Model gateway: one function for all LLM calls. Anthropic Claude by default: a strong tier for deep analysis, a fast tier for chat turns and Shiksha. Google Gemini as fallback. Model names in one config file. Cache, retries, cost log.
- Language: the four tasks of 4.1, routed as in 6.1.
- Guardrails: PII masking (3.5). Web pages fetched by Kasoti are data, never instructions.
- Limits: caps in INR, editable in admin: ₹25 per Kasoti session, ₹10 per Shiksha visitor per day, ₹3,000 per product per day. At 80% of a daily cap the team gets an email. At 100% the product shows "Resting for today. Please come back tomorrow."
- Usage and billing: each paid call writes a row to `usage_events` with an internal price in INR. No money moves.
- Subdomains: a Cloudflare wildcard `*.broadvaleai.com` shows "This name is reserved". Known names (khabri) pass through. Dynamic apps: [LATER].

## 5. Kasoti [NOW]

Risk pricing for any asset, for Indian people, businesses and institutions: a policy, a loan, a used car, a house, gold, a startup share, a crop, cyber risk.

### 5.1 Library
- Python package `kasoti`. One module per asset family. Shared: data loaders, a base risk model, a result schema, INR units.
- `describe()` returns the inputs a module needs and its review state. `price(inputs)` returns `{fair_price, range, risk_score, drivers, assumptions, confidence, sources}`.
- Methods: rules and actuarial tables where they exist, Monte Carlo for ranges. The LLM reads documents and fills gaps. It never sets the final number.
- A router picks the module from the user's words. If none fits, the "analogue" method reasons from comparable assets found by web research. That answer is labelled "Estimate, no model".
- Data: public and citable only, no scraping behind a login. Each source is a row in `kasoti_sources`: name, URL, fetch date, licence note. Each answer lists its sources.
- From web search, keep the URL, title, fetch date and our own one-line summary, not the provider's snippet.

Modules and their main public data, in build order (1–3 first):
1. Term life: IALM 2012–14 mortality table.
2. Gold: IBJA daily gold rate, making-charge ranges from research.
3. Used vehicle value: IRDAI IDV depreciation schedule, public listings by research.
4. Motor insurance: IRDAI third-party premium notification, IDV schedule.
5. Health cover: IRDAI annual report claim ratios, age bands.
6. Home: Bharat Griha Raksha standard policy, public rate research.
7. Personal loan: RBI repo rate, published bank lending rates.
8. Small business loan: RBI data, published MSME lending rates.

### 5.2 Chat
- A modern LLM chat: wide empty canvas, one message box at the bottom, streaming answers. The symbol and line stay until the first message.
- Opening: "Namaste. What should we price today?" Four example chips.
- **Push-to-talk** beside the box: hold to talk, release to send. A speaker button reads any answer aloud. Typing always works.
- Any Indian language, written or spoken. Kasoti replies in the same language.
- Uploads: PDF or photo of a policy, a quote, a bill.
- A side drawer lists past quotes, saved in the browser.
- Kasoti asks easy questions, one at a time, with tap-to-answer chips: need, capacity, tone (detail and caution), reason. Capacity is asked in bands ("₹5–10 lakh a year"), never exact figures.
- It stops when the module's inputs are filled, or after eight questions. Then it runs the module, web research and deep analysis. A live line shows the step.

### 5.3 Answer
- Depth: Short, Detailed or Expert. Kasoti picks a start from the user's answers. The user can change it. Short has no jargon. Expert explains terms inline.
- Top: "Pay about ₹X (range ₹A to ₹B)." Then "You take a medium risk because …" and a thin five-step risk bar.
- Folded below: how the price was built, main risk drivers, what could change it, what to ask the seller, sources with links, assumptions.
- Amounts in Indian style: ₹12,50,000, lakh, crore.
- The data date is shown. A saved quote older than 7 days shows "Old data. Re-price to update."
- Buttons: Re-price with a changed input, Share link, Save as PDF, Report a mistake.
- Compare two options side by side: [LATER].

### 5.4 Backend
- A tool-calling loop through the Model gateway. Tools: module pricing, web search (Brave Search API) and fetch, calculator, document reader.
- Deep analysis: the strong tier checks the number against the research and lists gaps. Gaps lower `confidence`.
- Rate limit by IP, plus the session cap. At 80% of the cap the loop stops research and answers, with lower `confidence`.

## 6. Shiksha [NOW]

121 small education apps (Appendix A). No login. Every Indian language. Content is translated or transcribed on demand.

### 6.1 Languages
- India's 22 scheduled languages plus English. [LATER]: Bhojpuri, Rajasthani, Tulu, Khasi, Mizo.
- Switcher in the nav, each language in its own script. A cookie keeps the choice. Right-to-left layout for Urdu, Kashmiri, Sindhi.
- `language_routes` holds the provider and quality (good, fair, none) per language and task. Order: Sarvam AI where it covers the language, then Google Cloud (Translation, Speech), then the Model gateway (translation only). Transliteration: Aksharamukha, an open-source rule library with no model cost.
- Voice quality starts at "none" for Bodo, Dogri, Santali, Kashmiri, Sindhi and Manipuri. Admin moves it up after a check of 10 sample sentences.
- Voice "none": hide the mic and show "Voice for this language is coming."
- UI strings are written once in English, translated on first use and cached in `translations`. Unreviewed text shows a small "machine translated" mark. Languages outside section 9 are reviewed when a user reports a problem.
- User content is translated or transcribed on request and cached by hash in `content_cache`.

### 6.2 Page and app shell
- `/shiksha`: a calm grid of apps by category, with search and a category filter.
- Card: name, one line, a small mark if voice works in the chosen language.
- Phase 1 builds the shell and the **30 apps** marked NOW in Appendix A. Other apps, and apps switched off in admin, show "Coming soon" and a "Notify me" email box.
- An app is a manifest: `id` (slug of the name), names per language, category, phase, inputs, handler.
- Four cheap handlers. `llm`: a fixed prompt through the Model gateway. `rule`: plain code, no model. `content`: curated text from `shiksha_content`. `calc`: a deterministic calculation.
- Every app has: language switch, Listen on any text, voice input, save in the browser, share link, print, "Report a mistake".
- Progress is saved in the browser. Account sync, and offline use as an installable web app: [LATER].

### 6.3 Content rules
- Sacred text: the model never writes or changes it. It only explains it.
- Gita Path: Sanskrit verses are imported once from a public-domain edition. Meanings are machine translated, marked and reviewable.
- Panchang Gyan: tithi, nakshatra, sunrise and sunset, computed in Python with Skyfield and the Lahiri ayanamsa. The user picks a city. Default: New Delhi. Festival dates: a curated table in `shiksha_content`, checked once a year.
- Exam apps: the model writes new practice questions. It never copies past-paper text. Each question is marked "Practice, not the real paper".
- Children use Shiksha. So every `llm` prompt carries the same safety rules: no sexual, violent, hateful or political-campaign content, and no advice on drugs, weapons or self-harm. A self-harm question gets a reply that points to a parent, a teacher or a national helpline.
- The model never asks for a name, age, school, address or phone number. Shiksha stores no child's data: only "Notify me" emails (`app_interest`) and report notes (`content_reports`), from adults. Both forms say so. The report form also says: enter no personal details.
