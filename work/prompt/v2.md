Tags: **[NOW]** = build in phase 1. **[LATER]** = design for it, do not build yet.

## 1. Fixed rules

- No tests for now. We add them when we take real money.
- One `.env` file holds all production keys. The user gives all browser logins, MCP access and API keys.
- Domain: broadvaleai.com. Three products: Surya, Kasoti, Shiksha.
- Symbols: Surya = the Sun. Kasoti = Krishna. Shiksha = Saraswati Mata.
- Tone: religious and auspicious. Respectful, never kitsch.

## 2. Look and feel

### 2.1 Themes
- Two themes from the live site (`docs/context/existing-site.md`): **Day** (light, green valley) and **Night** (noir, gold). Use the exact hex values as CSS variables.
- Home shows both at once. Other pages: Day 06:00–19:00, Night 19:00–06:00 (the live site rule). A sun/moon toggle in the nav overrides it. The choice is stored in a cookie.
- One accent per product, from the existing tokens: Surya = `mustard`, Kasoti = `canal`, Shiksha = `field`.

### 2.2 Visual rules
- Calm. Much empty space. Background, text and one accent. The accent covers less than 5% of a screen.
- 8 px spacing grid. Reading width at most 680 px. Grid width at most 1080 px.
- Four text sizes only: 14, 16, 20, 40 px. Display text in Anek Latin, weight 300. Body in Mukta.
- 1 px hairlines in `border`. No shadows. No gradients. Night theme has sharp corners, as on the live site.
- Icons: one thin line set (Lucide, 1.5 px stroke).
- Loading: a small diya flame with a soft pulse. Never a spinner.
- Copy: short and warm. No exclamation marks. Greet with "Namaste" in the chosen language.

### 2.3 Symbols and Sanskrit lines
- Phase 1 uses the traditional attributes, not figures. Each is simple SVG line art in the theme colors:
  - Surya: a sun disc with 12 fine rays.
  - Kasoti: a flute with one peacock feather.
  - Shiksha: a veena with a lotus.
- No photos, no stock art, no faces drawn by AI. Full figures of Krishna and Saraswati, drawn by a human artist: [LATER].
- Each product page opens with one Sanskrit line in Devanagari, meaning in the user's language below. Font: Tiro Devanagari Sanskrit, loaded only for these lines.
  - Surya: "तमसो मा ज्योतिर्गमय" — lead me from darkness to light (Brihadaranyaka Upanishad).
  - Kasoti: "यतो धर्मस्ततो जयः" — where there is dharma, there is victory (Mahabharata).
  - Shiksha: "विद्या ददाति विनयम्" — knowledge gives humility (Hitopadesha).

### 2.4 Motion and sound
- Slow, soft motion only: 600 ms fades. "Reduce motion" turns all motion off.
- A soft bell on first entry: [LATER], off by default.

## 5. Kasoti

### 5.1 Purpose
Risk pricing for any asset, for Indian people, businesses and institutions. Examples: a term or health policy, a loan, a used car, a house, gold, a startup share, a crop, business interruption, cyber risk.

### 5.2 Library [NOW]
- Python package `kasoti`. One module per asset family. Shared parts: data loaders, a base risk model, a result schema, INR units.
- Module interface: `describe()` returns the inputs it needs. `price(inputs)` returns `{fair_price, range, risk_score, drivers, assumptions, confidence, sources}`.
- Methods: rules and actuarial tables where they exist. Monte Carlo for ranges. The LLM reads documents and fills gaps. It never sets the final number.
- A router picks the module from the user's words. If none fits: the "analogue" method. It finds comparable assets by web research and reasons from them. The answer is labelled "Estimate, no model".

### 5.3 Phase 1 modules and data [NOW]
Build the first three, then the rest.

| Order | Module | Main public data |
| --- | --- | --- |
| 1 | Term life | IALM 2012–14 mortality table (Indian Assured Lives Mortality) |
| 2 | Gold | IBJA daily gold rate, making-charge ranges from research |
| 3 | Used vehicle value | IRDAI IDV depreciation schedule, public listings by research |
| 4 | Motor insurance | IRDAI third-party premium notification, IDV schedule |
| 5 | Health cover | IRDAI annual report claim ratios, age bands |
| 6 | Home | Bharat Griha Raksha standard policy, public rate research |
| 7 | Personal loan | RBI repo rate, published bank lending rates |
| 8 | Small business loan | RBI data, published MSME lending rates |

- Only public, citable data. No scraping behind a login.
- Each source is stored in `kasoti_sources` with name, URL, date fetched and licence note. Each answer lists the sources it used.

### 5.4 Chat [NOW]
- A modern LLM chat: wide empty canvas, one message box at the bottom, streaming answers. Flute symbol and the Sanskrit line at the top until the first message.
- Opening line: "Namaste. What should we price today?" Below it, four example chips.
- **Push-to-talk** beside the box: hold to talk, release to send. Speech to text per language. A speaker button reads any answer aloud. Typing always works.
- The user may write or speak in any Indian language. Kasoti replies in the same language.
- Uploads: PDF or photo of a policy, a quote, a bill.
- A side drawer lists past quotes, saved in the browser.

### 5.5 Conversation
1. The user says what to price.
2. Kasoti asks easy questions, one at a time, with tap-to-answer chips: need, capacity, tone (detail and caution), reason.
3. Capacity is asked in bands (for example "₹5–10 lakh a year"), never exact figures.
4. It stops when the module's inputs are filled. At most eight questions.
5. It runs the work: module call, web research, then deep analysis. A short live line shows the step ("Reading IRDAI data…").
6. It shows the answer.

### 5.6 Answer [NOW]
- Depth follows a three-step control: Short, Detailed, Expert. Kasoti picks a start from the user's answers. The user can change it.
- Top: "Pay about ₹X (range ₹A to ₹B)." Then one line on risk: "You take a medium risk because …"
- A thin five-step risk bar.
- Below, folded: how the price was built, main risk drivers, what could change it, what to ask the seller, sources with links, assumptions.
- Short level has no jargon. Expert level explains terms inline.
- Buttons: Re-price with a changed input, Share link, Save as PDF, Report a mistake.
- The disclaimer line (3.7).

### 5.7 Backend [NOW]
- A tool-calling loop through the Model gateway. Tools: module pricing, web search (Brave Search API) and fetch, calculator, document reader.
- Deep analysis: the strong tier checks the number against the research and lists gaps. Gaps lower `confidence`.
- Tables: `kasoti_sessions`, `kasoti_messages`, `kasoti_quotes`, `kasoti_sources`.
- Rate limit by IP and the session cap (4.5).
- Compare two options side by side: [LATER].

## 6. Shiksha

### 6.1 Purpose
121 small education apps. No login. Every Indian language. Content is translated or transcribed on demand.

### 6.2 Languages [NOW]
- The 22 scheduled languages plus English: Assamese, Bengali, Bodo, Dogri, Gujarati, Hindi, Kannada, Kashmiri, Konkani, Maithili, Malayalam, Manipuri (Meitei), Marathi, Nepali, Odia, Punjabi, Sanskrit, Santali, Sindhi, Tamil, Telugu, Urdu, English.
- [LATER]: Bhojpuri, Rajasthani, Tulu, Khasi, Mizo.
- Switcher in the nav. Each language is written in its own script. Choice stored in a cookie.
- Right-to-left layout for Urdu, Kashmiri, Sindhi.
- Provider per language and task, in table `language_routes` (language, task, provider, quality: good, fair, none):
  1. Sarvam AI for the languages it covers.
  2. Google Cloud (Translation, Speech) for the rest.
  3. The Model gateway as the last fallback for translation.
  4. Transliteration by an open-source rule library (Aksharamukha). No model cost.
- If voice quality is "none" for a language, hide the mic and show "Voice for this language is coming."

### 6.3 Language on demand [NOW]
- UI strings are written once in English. On first use they are translated and cached in `translations` (key, language, text, source: machine or human, reviewed).
- Unreviewed text shows a small "machine translated" mark.
- Before launch the team reviews Hindi, Bengali, Marathi, Tamil, Telugu and Gujarati. Other languages are reviewed when a user reports a problem.
- User content (a lesson, a question, a voice note) is translated or transcribed on request and cached by hash in `content_cache`.
- A "Listen" button on any text.

### 6.4 Shiksha page [NOW]
- Veena symbol, the Sanskrit line, then a calm grid of apps by category (Appendix A). Search box and category filter.
- Each card: name, one line, a small mark if voice works in the chosen language.
- Phase 1 builds the shell and **30 apps** (NOW in Appendix A). Others show "Coming soon" with a "Notify me" email box. It writes to `app_interest`.

### 6.5 App shell [NOW]
- Each app is a manifest: `id` (slug of the name), names per language, category, phase, inputs, handler.
- Four handler types keep apps cheap:
  1. `llm`: a fixed prompt through the Model gateway.
  2. `rule`: plain code, no model (for example Pahade, Lipi Setu).
  3. `content`: fixed, curated text from the database (for example Gita Path).
  4. `calc`: a deterministic calculation (for example Panchang Gyan).
- Shared by all apps: language switch, Listen, voice input, save in the browser, share link, print, "Report a mistake" (writes to `content_reports`).
- Progress is saved in the browser. Sync to an account: [LATER]. Offline use as an installable web app: [LATER].

### 6.6 Sacred and fixed text [NOW]
- The model never writes or changes sacred text. It only explains it.
- Gita Path: Sanskrit verses imported once from a public-domain edition. One human checks them against a Gita Press print before launch. Meanings are machine translated, marked, and reviewable.
- Panchang Gyan: tithi, nakshatra, sunrise and sunset computed in Python with Skyfield (MIT licence) and the Lahiri ayanamsa. The user picks a city. Default: New Delhi. Festival dates come from a curated table, checked once a year.

## 10. Decisions log

### Round 1 (kept unless noted)
1. Stack: Next.js on Cloudflare, Python FastAPI on Fly.io for Kasoti. Same as the live site; Python is a hard need.
2. Both themes on every page. Home shows both. Other pages follow the clock rule with a toggle.
3. People half: only "Coming soon", no button.
4. No public login in phase 1. Surya is closed and login adds friction.
5. Pre-registration protected by Turnstile and a honeypot.
6. Languages: 22 scheduled plus English.
7. Kasoti: the LLM never sets the final number. Trust and repeatability.
8. Kasoti asks at most eight questions.
9. **Changed in round 2.** Was "line art of the deities". Now: attributes only (sun, flute and feather, veena and lotus) in phase 1. An AI-drawn deity face risks disrespect. Figures by a human artist later.
10. Shiksha ships 30 apps in phase 1.
11. Surya in phase 1 is internal modules only.

### Round 2
1. Phase 1 apps: v1 said 24 NOW, but its table had 26. Keep the 26 and add Lipi Setu, Saral Path, Uttar Jaanch and Cyber Suraksha. All are cheap (`llm` or `rule`) and widely useful.
2. Speech and translation: best provider per language from a routing table. Sarvam first, Google for the rest, LLM as last fallback. No single provider covers all 22 languages well.
3. LLM: Anthropic Claude by default, Google Gemini as fallback. Caps: ₹25 per Kasoti session, ₹10 per Shiksha visitor per day, ₹3,000 per product per day. Low enough to be safe, high enough for a deep answer.
4. Kasoti modules: the eight from v1, ordered by how good the public data is. Term life, gold and used vehicle first. Only public, citable sources.
5. No customer login in phase 1. Quotes are saved in the browser and shared by link.
6. Legal: guidance disclaimer, DPDP-based privacy page, no commission, no product recommendation, PII masking, 90-day chat retention.
7. Translation review: team reviews six major languages before launch. Others on user report. Unreviewed text is marked.
8. Gita text is curated and human-checked. Panchang is computed with Skyfield. The model never writes sacred text or computes dates.
9. Keep "Business" and "People", each with a Hindi word under it.
10. No intro screen. A 1.2 s sunrise on the seam on the first visit only.
11. New: all writes go through server routes and RLS blocks anonymous access. Changed from v1 "anyone can insert". Safer and one place for checks.
12. New: Surya product chips on `/business` collect interests. Cheap signal for which products to build first.
13. New: Shiksha handler types (`llm`, `rule`, `content`, `calc`). Keeps the cost of each new app low.
14. New: confirmation email by Amazon SES. AWS is already a backend.
15. New: web search by Brave Search API. It does not depend on the LLM provider.
